# Вечерняя звезда — сканер OKX с сообщениями в Telegram

Бот каждые 15 минут просматривает самые ликвидные USDT-перпетуалы OKX и присылает сообщение, когда начинается падение после звезды.

## Как это работает

Схема по свечам (на 1ч и 4ч):

1. **Свеча 1 — звезда.** Бот находит её сразу после закрытия на 1ч или 4ч.
2. **Свеча 2 — основное движение.** Пока она формируется, бот следит за свечами 15м и 30м этой монеты. Как только одна из них закрылась ниже минимума звезды, приходит сообщение. Так вы получаете сигнал в начале движения, а не после закрытия всей свечи 2.
3. **Свеча 3 — остатки.** Сообщений по этой звезде уже не будет.

Сообщения не приходят, если:
- цена закрылась выше максимума звезды (сценарий отменён);
- свеча 2 закончилась без падения;
- падение уже ушло слишком далеко от звезды (настройка `MAX_CHASE_RANGES`);
- по этой монете уже было сообщение за последние 4 часа (`COIN_COOLDOWN_HOURS`).

Бот запоминает, какие звёзды уже видел, поэтому одна и та же звезда не отправляется дважды.

Свечи 30м бот собирает из двух свечей 15м, поэтому на проверку звезды уходит один запрос к бирже, а не два.

## Что в сообщении

```
🌇 Вечерняя звезда · SOL/USDT

Цена сейчас: 105.85 (19:16, Ташкент)
Звезда: 1ч, закрылась 27.10 19:00
RSI(14): на звезде 1ч — 74 (перекупленность), сейчас на 15м — 41 (нейтрально)
Объём: звезда ×2.5 от среднего, свеча пробоя ×1.8

Падение началось: свеча 15м закрылась в 19:15 на 105.85,
ниже минимума звезды (106.15) на 0.28%

Отмена сценария: закрытие выше 108.45 (+2.5% от цены сейчас)

График TradingView
```

Цифры в примере условные. Все времена по Ташкенту. Уровней входа бот не предлагает: точку входа вы выбираете сами.

## Скорость работы

Между запросами к бирже бот делает паузу 8 секунд (`REQUEST_PAUSE`), чтобы биржа не блокировала адрес GitHub. Поэтому проход по 75 монетам на одном таймфрейме занимает около 10 минут. Чтобы запуск не растягивался, за один запуск звёзды ищутся только на одном таймфрейме: когда закрывается 1ч, проверяется он, а 4ч (его свеча закрывается в 05:00, 09:00, 13:00, 17:00, 21:00 и 01:00 по Ташкенту вместе с 1ч) проверяется в следующем запуске, примерно через 15 минут. Падение после такой звезды бот всё равно увидит: он смотрит уже закрытые свечи 15м внутри свечи 2.

Чтобы срочное не ждало долгого, в каждом запуске сначала проверяются уже найденные звёзды (на каждую уходит 8 секунд), и только потом ищутся новые. Если биржа недоступна, поиск прерывается после 5 ошибок подряд, а запуск в любом случае укладывается в 25 минут.

## Что такое вечерняя звезда в этом боте

Кроме формы звезды (длинная верхняя тень, маленькое тело, почти нет нижней тени) бот проверяет свечу перед ней: это должна быть большая зелёная свеча, а тело звезды не больше 70% её тела. Если перед звездой красная или обычная маленькая свеча, сообщения не будет. Пороги — `PREV_GREEN_BODY_MULT` и `STAR_BODY_VS_PREV_MAX` в `config.py`.

## Установка (один раз)

1. На GitHub создайте новый репозиторий. Лучше **Public**: в публичных репозиториях Actions бесплатны без ограничения по минутам, а в приватных 2000 бесплатных минут в месяц не хватит на запуск каждые 15 минут. В коде нет паролей, секреты хранятся отдельно.
2. Распакуйте архив и загрузите все файлы в репозиторий: Add file → Upload files. Папку `.github` тоже нужно перетащить.
3. Settings → Secrets and variables → Actions → New repository secret. Добавьте два секрета:
   - `TELEGRAM_BOT_TOKEN` — токен бота из @BotFather;
   - `TELEGRAM_CHAT_ID` — номер вашего чата.
4. Вкладка Actions → слева «Scan» → Run workflow → отметьте `test_telegram` → Run. В Telegram должно прийти тестовое сообщение.
5. Дальше бот запускается сам каждые 15 минут. Первые запуски по расписанию могут появиться через 5–15 минут.

Если в Actions кнопка Run workflow не появилась, нажмите на вкладке Actions «I understand my workflows, go ahead and enable them».

## Настройки

Все числа в файле `config.py`: монеты, таймфреймы, доли свечи для звезды, уровень подтверждения. Изменить файл можно прямо на GitHub (значок карандаша) и сохранить кнопкой Commit.

- Хотите больше сообщений: увеличьте `MAX_CHASE_RANGES` до 2, поднимите `BODY_MAX` или `LOWER_WICK_MAX`, или поставьте `CONFIRM_LEVEL = "body"`.
- Хотите меньше: включите `REQUIRE_RED_BODY = True` и `MIN_VOLUME_MULT = 1.5`.
- Хотите быстрее при той же паузе: уменьшите `TOP_COINS` (при 30 монетах проход занимает около 4 минут).

## Как проверить, что бот работает

Actions → любой запуск → Scan → шаг «Запуск сканера». В конце лога строка «Итог»: сколько монет проверено, сколько ошибок запросов к бирже, сколько новых звёзд, сколько на наблюдении, сколько отправлено и сколько минут работал запуск. Если ошибок много, увеличьте `REQUEST_PAUSE` в `config.py`.

Пробный запуск без отправки в Telegram: Run workflow → `dry_run`. Текст сообщений появится в логе.

## Важно

- GitHub запускает расписание с задержкой, иногда в несколько минут. Для свечей 15м это означает, что сообщение может прийти не точно в момент закрытия.
- В публичном репозитории без изменений GitHub выключает расписание через 60 дней. Тогда на вкладке Actions нужно нажать Enable.
- Это инструмент поиска ситуаций, а не гарантия результата.
